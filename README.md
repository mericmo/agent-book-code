# 《面向 Offer 学习 Agent 核心技术》配套代码与资料

本仓库是《面向 Offer 学习 Agent 核心技术》一书的配套仓库，收录两样东西：

- **各章示例代码**：`part-1` 到 `part-7` 按书的七个部分分目录，每个子目录对应一章，脚本可以单独运行，输出与书中的表格和结论对得上。
- **引用资料**：`docs/` 目录存放全书引用的 50 篇 arXiv 论文 PDF，以及一份把论文、公告、开源项目与正文引用位置对应起来的总清单 `docs/参考资料.md`。

代码的定位是**教学骨架**：每个脚本只保留讲清一个机制所必需的部分，几十行，去掉业务外壳。它用于在读书时把抽象描述跑成看得见的输出，不是生产可用的实现，也不追求复现论文里的指标。

## 二、环境准备

需要 Python 3.9 及以上版本（脚本用到了 `list[list[int]]` 这类内置泛型标注，实测环境为 3.13）。

```bash
git clone https://github.com/mericmo/agent-book-code.git
cd agent-book-code

python -m venv venv
# Windows
venv\Scripts\activate
# macOS / Linux
source venv/bin/activate

pip install -r requirements.txt
```

`requirements.txt` 只有四个包：

| 包 | 用途 | 谁需要 |
| :--- | :--- | :--- |
| `openai` | OpenAI 兼容的 SDK，调模型与工具调用 | 第 1 章 1 个、第 7 章 2 个脚本 |
| `pydantic` | 定义工具参数 schema、做校验 | 第 7 章 2 个脚本（工具定义与校验闭环） |
| `mcp` | MCP 官方 SDK，写 server 与 client | 第 8 章的 server 与 client |
| `python-dotenv` | 从 `.env` 读配置 | 需要调模型的 2 个示例 |

**大多数脚本只用标准库**，不装依赖也能跑。第 8 章的 `mcp_wire.py` 与 `shell_injection.py`、第 10 章以后的全部脚本都属于这一类。

### 需要模型密钥的脚本

第 1 章的 `agent_loop.py` 与第 7 章的 `toools_demo.py` 会真实调用模型。在仓库根目录放一个 `.env`（该文件已在 `.gitignore` 中，不会入库）：

```ini
MODEL_API_KEY=sk-xxxxxxxx
MODEL_BASE_URL=https://api.deepseek.com/v1
MODEL_NAME=deepseek-chat
```

三个变量分别对应密钥、OpenAI 兼容的接口地址、模型名。换任何 OpenAI 兼容的服务，只改后两个值即可。

## 三、怎么跑

**一句话原则：脚本之间不互相 import，也没有共享的数据文件，从仓库根目录直接运行即可。** 只有两个例外，见下面的说明。

```bash
# 纯标准库的脚本，直接跑
python part-5/12/shared_state_race.py

# 需要依赖的，先装 requirements.txt，同样直接跑
python part-3/07/validation_loop.py

# 需要模型密钥的，在根目录放好 .env 再跑
python part-1/01/agent_loop.py
```

两个脚本需要额外说明：

- `part-3/08/mcp_client.py` 会以子进程方式拉起同目录的 `mcp_server.py`，请在 `part-3/08` 目录内运行，否则找不到服务器脚本。它一次跑完五步：初始化、列工具、列资源、调工具、读资源。
- `part-3/09/skill_lint.py` 是一个命令行工具，需要传入技能目录：

  ```bash
  python part-3/09/skill_lint.py ../pdf-tool-2026
  ```

  对仓库自带的那个坏样例，它会报出 6 处问题：命名不合规、name 与目录名不一致、description 含泛词、缺少负向排除、引用的 `references/forms.md` 不存在、把「参见脚本」当成阅读而非运行。

所有脚本的输出都打印在标准终端里，没有图片、日志文件或临时目录产生。第 12 章的 `shared_state_race.py` 用了固定交错顺序，输出可复现；第 14 章的 `orchestration_vs_coord.py` 用了 `random`，但设了固定种子 `random.seed(7)`，多次运行的结论一致。

## 五、docs 目录：引用资料

`docs/` 存放全书引用的原始资料，按引用方式分成两类：

**50 篇 arXiv 论文 PDF。** 命名规则是 `序号-论文简称-arXiv编号.pdf`，例如 `01-ReAct-2210.03629.pdf`。序号就是清单第一节里的编号，按号回到表格能查到标题、作者、发表年份与它在书里的引用位置。

**`参考资料.md`。** 这是整个资料目录的总索引，按四类组织：

| 分类 | 内容 | 数量 |
| :--- | :--- | :--- |
| 一、学术论文 | 已下载 PDF 的论文，含标题、作者、年份、arXiv 编号、本地文件名、引用位置 | 50 篇 |
| 二、官方公告 / 工程博客 / 研究报告 / 榜单 | 只给链接 | 47 条 |
| 三、开源项目与产品官网 | 只给链接，含本仓库地址 | 21 条 |
| 四、法律案件报道 | 只给链接 | 3 条 |

每条都标了「引用位置」，写明它被哪一章引用，少数条目还标注了更细的场合（例如「第 3 章（面试追问）」）。正文直接标注了 arXiv 编号的 16 处在该列用 ★ 标出，其余是书中具名引用、清单补齐编号的论文。清单末尾还附了核对结论与时效性提醒，例如 LMArena 已迁至新域名、OSWorld 官网已迁移。

想找某一章的依据，从「引用位置」这一列反查最快；想找某篇论文在书里用在哪，按 PDF 文件名里的编号回到第一节的表格即可。

## 六、代码与书稿的约定

1. **脚本是骨架，不是实现。** 文件头的注释写明了它简化了什么。例如 `parallel_tools.py` 用 `asyncio` 演示执行顺序，真实系统还要处理超时与取消；`skill_lint.py` 用子串匹配做启发式检查，会误报也会漏报。
2. **成本与耗时是示意值。** `verification_tiers.py` 里的 token 成本、`progress_guard.py` 里的轮次阈值，都是为了把量级差异摆出来，不是实测数据。
3. **输出的数字与正文对得上。** 例如 `verification_tiers.py` 打印的「漏检 0 处 / 5 处」，与书里验证分级一节的对比数据同源。如果改动脚本逻辑，书里的数字也要同步改。
4. **协议细节以官方 spec 为准。** `mcp_wire.py` 按 JSON-RPC 骨架还原报文，不是官方实现；`task_state_machine.py` 的转移表是教学用简化版，生产实现请对照官方文档。
5. **不收录会被环境改写的东西。** `.env`、`venv/`、`.idea/`、`__pycache__/` 都在 `.gitignore` 里。
